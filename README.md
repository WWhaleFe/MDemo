# MDemo

**노션과 잘 이어지는 마크다운 메모앱.** macOS 바탕화면에 떠 있는 스티키 노트로 빠르게 적고,
노션과 복사 · 붙여넣기로 서식째 주고받는다. 이것이 이 앱을 만든 목적이다.

- **메모 → 노션:** 메모에서 ⌘C로 복사해 노션에 ⌘V로 붙여 넣으면 제목 · 목록 · 체크박스 · 번호 목록 ·
  인용 · 코드 · 표 · 굵게/기울임/취소선이 노션 블록으로 그대로 들어간다.
- **노션 → 메모:** 노션에서 복사해 메모에 붙여 넣으면 같은 서식으로 들어간다. 하위 목록 단계도 지킨다.
- 쓰는 동안에는 마크다운 기호를 숨기고 서식만 보여 준다 (`# `, `- [ ] `, `**굵게**`를 치면 바로 바뀐다).
- 저장은 늘 표준 마크다운이다. 메모 하나가 `.md` 파일 하나라 노션 · Obsidian 등 다른 도구에서도 읽힌다.
- 메뉴바에 상주하고, 메모는 다른 창 위에 떠 있어 일하면서 바로 적을 수 있다.

(0.9.0까지 이름은 MemoApp이었다. 다른 앱과 겹쳐 저장소·코드·앱 식별자·저장 폴더를 모두 MDemo로 바꿨다.
예전 버전의 메모와 설정은 MDemo를 처음 켤 때 새 자리로 복사된다. 원본은 지우지 않는다.)

## ⬇️ 설치 (macOS)

Homebrew로 설치하는 것이 가장 간단하다. 첫 실행 차단(Gatekeeper)도 알아서 풀어 준다.

```sh
brew install --cask wwhalefe/tap/mdemo
brew update && brew upgrade --cask mdemo   # 업데이트
```

Homebrew 6 이상에서 `untrusted tap` 오류가 나면 먼저 `brew trust --cask wwhalefe/tap/mdemo`를 실행한다.
업데이트한 뒤에는 메뉴바에서 MDemo를 종료하고 다시 열어야 새 버전이 뜬다.

직접 받으려면 [최신 릴리스](https://github.com/WWhaleFe/MDemo/releases/latest)에서 `MDemo-vX.Y.Z.zip`을 받아
압축을 풀고 **응용 프로그램** 폴더로 옮긴다. `.dmg`를 받았다면 열어서 Applications로 끌어다 놓는다.

- 유니버설(Apple Silicon + Intel), macOS 14 이상.
- 아직 공증(notarization)을 받지 않은 임시 서명 앱이다. 처음 열면 macOS가 막는데,
  **시스템 설정 → 개인정보 보호 및 보안 → "그래도 열기"**를 누르면 된다.
  (macOS 15부터는 Finder 우클릭 → "열기"로는 넘어가지 않는다.)
- 메뉴바 앱이라 Dock에는 뜨지 않는다. 화면 위쪽 메뉴바의 메모 아이콘에서 쓴다.

## 🖼 메모 안 이미지 · 글자 읽기 · AirDrop

- 이미지를 붙여 넣거나 끌어 놓거나 서식 막대의 이미지 단추로 메모 안에 넣는다. 파일은 메모의 `attachments` 폴더에 따로 저장되고 본문에는 `![설명](attachments/파일 =너비)` 한 줄만 남는다.
- 모서리를 끌어 크기를 바꾸고, 우클릭으로 복사 · 크기(25/50/100%/너비 맞춤) · 다른 이름으로 저장 · Finder에서 보기 · 지우기.
- 우클릭 "글자 읽어서 아래에 넣기 / 글자로 바꾸고 이미지 지우기": 맥 안에서(Vision) 한국어 · 영어를 읽어 제목 · 목록 · 체크박스를 마크다운으로 바꾼다. 미리보기에서 고쳐 넣는다.
- AirDrop으로 이미지 받기: 메모 창 맨 위 단추(커서 자리에), 목록 우클릭(맨 위 · 맨 아래, 메모를 열지 않고), 메뉴바와 목록 툴바(새 메모로).
- 이미지로 내보내기: 메모 창 맨 위 단추와 목록 우클릭. PNG 저장 · 공유(AirDrop 등) · 복사, 1배 · 2배.
- 메모 복제(목록 우클릭), 목록 줄 앞 손잡이로 순서 바꾸기("직접 순서" 정렬).
- 동기화는 구글 드라이브 하나다. iCloud 동기화와 iPhone 읽기용 사본은 Windows판이 쓸 수 없어 없앴다.

## 🗂 메모 목록: 네 가지 보기와 파이프

메뉴바의 **메모 목록…**에서 메모를 네 가지 모양으로 본다. 위쪽 단추로 바꾸고, 고른 보기는 기억한다.
목록 창 위쪽의 핀 단추(또는 메뉴바의 "메모 목록 창 항상 위에")로 목록 창을 다른 창 위에 고정할지 정한다. 기본은 꺼짐이다.
메뉴바의 **화면 모드**에서 시스템 설정 따르기 · 라이트 · 다크를 고른다. 목록 창의 화면 모드 단추는 누를 때마다 바뀌고, 우클릭하면 목록에서 고른다.
검색칸 왼쪽 돋보기에서 찾는 범위(제목+본문 · 제목 · 본문)와 그룹을 정한다. 본문은 메모 끝까지 찾는다.

- **목록** - 오늘 · 이번 주 · 이전으로 묶은 줄. 흐름에 든 메모는 "흐름 이름 2/4" 칩이 붙는다.
- **그리드** - 같은 크기 카드. 체크박스 메모는 진행 막대로 보인다.
- **벤토** - 연결이 많고 최근에 고친 메모일수록 큰 카드. 우클릭 → 크기로 직접 정할 수도 있다.
- **보드** - 메모를 화이트보드에 자유롭게 놓고, 카드 가장자리의 라임 단자를 끌어 다른 카드에 놓으면 **파이프**로 이어진다.
  - 아래 도구 막대에서 선 종류를 고른다. 기본 6개와 더 보기 4개를 제공한다.
  - 선을 더블클릭하면 최대 20자의 이름을 쓸 수 있다. Enter 또는 바깥 클릭으로 확정하고 Esc로 취소한다. 비우면 이름을 지운다.
  - 이름표는 기본으로 항상 보이며, ⓘ 옆 이름표 단추나 메뉴바 보기 설정에서 끌 수 있다. 35% 아래에서는 자동으로 숨긴다.
  - ⋯ 메뉴에서 단추 모양과 보일 선을 정한다. 좁은 창에서는 오른쪽 선부터 더 보기로 접힌다.
  - 보드 이미지 내보내기에서 파이프와 선 이름표를 따로 고를 수 있다.
  - 파이프를 눌러 고르면 "연결 끊기"가 나온다. Delete 키로도 끊는다.
  - 흐름에 든 카드를 고르면 왼쪽 위에서 그 흐름을 **모두 띄우기 · 순서대로 놓기** 할 수 있다.
  - 자동 정리, 전체 보기(⌘0), 확대 · 축소, 미니맵.

| 선 | 이름 | 뜻 |
|---|---|---|
| 실선 | 연결 | 같은 주제로 이어진 메모 |
| 실선 → | 흐름 | 다음 단계, 순서가 있는 이어짐 |
| 실선 ↔ | 상호 | 서로 주고받는 대등한 관계 |
| 점선 | 관련 | 느슨하게 관련된 메모 |
| 점선 → | 참고 | 이 메모가 저 메모를 참고하거나 기댐(화살표 쪽이 참고 대상) |
| 점선 ↔ | 서로 참고 | 서로를 참고하는 약한 양방향 관계 |
| 실선 + 시작 점 + 끝 갈퀴 | 포함 | 큰 주제(점 쪽)가 작은 메모를 품음 |
| 실선 + 끝 막대 ⊣ | 막힘 | 이 일이 끝나야 저 일(⊣ 쪽)을 할 수 있음 |
| 물결선 + 가운데 ✕ 원 | 반대 | 서로 부딪히는 생각 · 대안 |
| 이중 실선 | 같음 | 같은 내용 · 중복 |

흐름으로 이은 메모는 바탕화면에 띄운 메모 창 아래에도 `‹ 이전 메모 · 다음 메모 ›` 줄이 붙어 차례로 따라갈 수 있다.
연결은 메모 파일 앞머리에 `links: flow:<ID>,related:<ID>`로 남고(스키마 v3), 직접 쓴 이름은 `flow:<ID>~%EA%B2%80%ED%86%A0%20%ED%9B%84`처럼 퍼센트 인코딩해 저장한다. 보드 위치는 데이터 폴더의 `board.json`에 저장된다.

## 📋 노션과 주고받기

메모와 노션 사이에서는 그냥 ⌘C · ⌘V를 쓰면 된다.

| | 메모 → 노션 | 노션 → 메모 |
|---|---|---|
| 제목 1~3 · 글머리 · 번호 · 체크박스 · 인용 · 구분선 | ✓ | ✓ |
| 하위 목록 단계 | ✓ (4칸 들여쓰기) | ✓ (2칸 · 4칸 · 탭 모두 인식) |
| 코드 박스 · 표 | ✓ | ✓ |
| 굵게 · 기울임 · 취소선 · 코드 글자 | ✓ | ✓ |
| 글자 색 · 형광펜 | 글자만 (노션 마크다운에는 색 문법이 없다) | — |

- 화면에는 `•` · `☐` 같은 표식만 보이지만, 복사할 때는 고른 부분을 마크다운으로 되돌려 넣는다.
  한 줄 안의 일부만 고르면 글자 서식만 가져간다.
- 글이 있는 줄 가운데에 붙여 넣으면 그 줄의 모양(목록 · 제목)은 지키고 글자 서식만 들어간다.
- 서식 없이 글자만 붙여 넣으려면 ⌥⇧⌘V.

## ☁️ 구글 드라이브 동기화

메뉴바 아이콘의 "동기화" > "구글 계정으로 로그인…"을 누르고 브라우저에서 로그인만 하면 됩니다.
동기화는 구글 드라이브 하나입니다. 맥과 앞으로 나올 Windows판이 같은 드라이브로 맞추도록 iCloud 동기화는 없앴습니다. 로그인하지 않으면 동기화하지 않고 이 맥에만 저장합니다.

예전 판에서 iCloud로 동기화하던 분은 이 맥의 메모가 그대로 있습니다. 구글로 로그인하면 첫 동기화가 이 맥의 메모를 드라이브로 올립니다. iCloud Drive의 `MDemo` 폴더는 지우지 않으니, 필요 없으면 직접 정리해 주세요.

- **권한은 앱이 만든 파일뿐입니다.** `drive.file` 범위만 요청하므로 드라이브에 있는 다른 파일은 볼 수 없습니다. 드라이브 최상위의 `MDemo` 폴더 아래에 메모 폴더 구조가 그대로 올라갑니다.
- **토큰은 이 맥의 키체인에만 둡니다.** iCloud 키체인으로 동기화하지 않고, 짧게 쓰는 접근 토큰은 메모리에만 있습니다.
- **암호 메모는 올리지 않습니다.** 파기한 메모와 이 기기 전용 메모도 올라가지 않습니다.
- **드라이브에서 지울 때는 휴지통을 거치지 않고 영구 삭제합니다.** 메모를 파기하면 드라이브에서도 바로 사라집니다.
- **로그아웃하면 토큰을 폐기합니다.** 키체인 항목, 이 맥의 드라이브 사본 폴더, 동기화 기록을 지웁니다. 메모 자체는 그대로 남습니다.
- 첫 동기화는 합치기만 합니다. 양쪽 파일을 모두 살리고 아무것도 지우지 않습니다. 목록이나 내려받기가 하나라도 실패하면 그 회차는 통째로 멈추고 아무것도 지우지 않습니다.

개발자용 설정: 로그인 기능은 클라이언트 값이 있어야 켜집니다.

1. Google Cloud 콘솔에서 프로젝트를 만들고 Google Drive API를 사용 설정합니다.
2. OAuth 동의 화면을 "외부"로 만들고 게시합니다.
3. "데스크톱 앱" 유형의 OAuth 클라이언트를 만듭니다.
4. `App/Resources/GoogleOAuth.example.plist`를 `App/Resources/GoogleOAuth.plist`로 복사해 `CLIENT_ID`와 `CLIENT_SECRET`을 넣습니다. 이 파일은 git에 올라가지 않으며, `make build` 때 앱 번들에 복사됩니다. 파일이 없으면 메뉴에 "구글 로그인 설정이 없습니다"가 흐리게 보입니다.

## 📤 노션에 올리기

메뉴바 아이콘의 "노션" > "노션 계정으로 로그인…"을 누르고 브라우저에서 허락하면 됩니다. 로그인하지 않으면 노션과 통신하지 않습니다.

1. **로그인**: 브라우저에서 노션 로그인과 MDemo가 볼 수 있는 페이지 허락을 마칩니다.
2. **올릴 곳 고르기**: "노션" > "올릴 곳 고르기…"에서 페이지 또는 데이터베이스 하나를 고릅니다. 페이지를 고르면 그 아래 하위 페이지로, 데이터베이스를 고르면 그 데이터베이스의 새 항목으로 올라갑니다(제목 속성에 메모 제목이 들어가고 다른 속성은 비워 둡니다). 목록이 비어 있으면 노션에서 페이지 오른쪽 위 ⋯ > 연결에 MDemo를 추가하거나 다시 로그인해 허락할 페이지를 고르세요.
3. **올리기**: 목록 · 그리드 · 벤토 · 보드의 메모 우클릭 "노션에 올리기"(여러 개를 고르면 모두), 또는 메모 창 안 우클릭 "노션에 올리기". 제목 · 목록 · 체크박스 · 인용 · 코드 · 표 · 구분선 · 굵게 · 기울임 · 취소선 · 링크 · 글자 색 · 형광펜 · 이미지가 노션 블록으로 올라갑니다. 이미지를 올리지 못하면 그 자리에 "[이미지]"가 들어갑니다.
4. **다시 올리기**: 이미 올린 메모는 같은 페이지의 제목과 내용을 새로 바꿉니다(노션에서 직접 고친 내용은 사라집니다). 페이지를 노션에서 지웠다면 새로 만들고, 올릴 곳을 바꾸면 새 곳에 새로 만듭니다.

- **암호 메모는 올라가지 않습니다.** 암호 메모 · 이 기기 전용 메모 · 파기한 메모는 메뉴가 흐려지고, 올리는 코드에서도 노션을 부르기 전에 한 번 더 막습니다. 여러 개를 고르면 이들만 빼고 올린 뒤 "암호 메모 N개는 올리지 않았습니다"라고 알려 줍니다. 잠금을 푼 상태여도 올리지 않습니다.
- **메모 내용은 앱이 노션과 직접 주고받습니다.** 중계 서버(`Server/notion-oauth`)는 로그인 코드를 토큰으로 바꾸는 일만 하고 메모 내용은 지나가지 않습니다.
- **토큰은 이 맥의 키체인에만 둡니다.** iCloud 키체인으로 동기화하지 않습니다. 토큰이 만료되면 갱신하고, 갱신할 수 없으면 "다시 로그인해 주세요"라고 알려 줍니다.
- **로그아웃하면** 키체인 항목 · 올릴 곳 설정 · 페이지 연결 기록(`~/Library/Application Support/MDemo/notion-links.json`, 동기화와 백업에 들어가지 않음)을 지웁니다. 노션에 올라간 페이지는 그대로 남습니다.
- 노션이 알려 주는 한도(글 2000자, 한 번에 100블록)에 맞춰 나눠 보내고, 한도 초과(429)나 서버 오류는 잠깐씩 기다리며 최대 5번 다시 시도합니다.

개발자용 설정: 로그인 기능은 노션 공개 통합과 중계 서버가 있어야 켜집니다.

1. 노션 개발자 포털에서 "공개" 통합을 만들고 Redirect URI를 `https://<중계 서버 주소>/api/notion/callback`으로 등록합니다. 콘텐츠 읽기 · 쓰기 · 삽입 권한을 켭니다.
2. 중계 서버를 배포합니다. 배포와 환경 변수는 `Server/notion-oauth/README.md`를 따릅니다. 비밀키는 서버에만 둡니다.
3. `App/Resources/NotionOAuth.example.plist`를 `App/Resources/NotionOAuth.plist`로 복사해 `CLIENT_ID`와 `RELAY_URL`(중계 서버 주소)을 넣습니다. 이 파일은 git에 올라가지 않으며, `make build` 때 앱 번들에 복사됩니다. 파일이 없으면 메뉴에 "노션 로그인 설정이 없습니다"가 흐리게 보입니다.

## 🔄 업데이트

메뉴바 메뉴 아래쪽(종료 바로 위)에 버전과 업데이트 항목이 있다.

- **업데이트 확인…** — GitHub의 최신 릴리스와 비교해 결과를 한 줄로 보여 준다 (✓ 최신 / 🔵 새 버전 / ⚠️ 실패).
- **최신 버전 다운로드** — 최신 릴리스의 zip을 다운로드 폴더에 받고 Finder에서 보여 준다.
  다 받은 뒤 다시 누르면 Finder에서 다시 보여 주고, 실패했으면 릴리스 페이지를 연다.
  임시 서명 앱이라 자동으로 바꿔 끼우지 않는다 — 압축을 풀어 응용 프로그램에 덮어쓰면 된다.
- **릴리스 페이지 열기** — 버전별 변경 내용과 파일을 브라우저에서 본다.
- Homebrew로 설치했다면 zip을 받는 대신 `brew update && brew upgrade --cask mdemo`로 올린다.
- **업데이트 자동 확인** — 켤 때 한 번, 그 뒤 하루에 한 번 확인한다. 새 버전은 버전마다 한 번만 알린다.
- 메모와 설정은 앱 밖(`~/Library/Application Support/MDemo/Data`, 사용자 기본값)에 있어서
  앱을 바꿔도 그대로 남는다.
- 앱이 외부와 통신하는 것은 이 업데이트 확인과 (로그인했을 때만) 구글 드라이브 동기화 · 노션 올리기뿐이다 (NFR-07). 업데이트 확인은 메모 내용을 보내지 않는다.

## 📦 릴리스 절차

버전은 `App/Resources/Info.plist` 한 곳에서 관리한다.

1. `CFBundleShortVersionString`(예: `0.9.1`)과 `CFBundleVersion`(빌드 번호, 1씩 증가)을 올린다.
2. `make test && make dist` — `build/dist/MDemo-vX.Y.Z.zip`과 `.dmg`가 생긴다.
3. 커밋: `vX.Y.Z: 바뀐 점 요약`
4. 태그와 릴리스: `gh release create vX.Y.Z build/dist/MDemo-vX.Y.Z.zip build/dist/MDemo-vX.Y.Z.dmg --title "MDemo vX.Y.Z" --notes-file <노트>`
5. Homebrew: [WWhaleFe/homebrew-tap](https://github.com/WWhaleFe/homebrew-tap)이 30분마다 최신 릴리스를 확인해
   `Casks/mdemo.rb`의 버전과 sha256을 저절로 맞춘다. 손댈 것은 없다.
   단, zip 이름(`MDemo-vX.Y.Z.zip`)과 그 안의 `MDemo.app`, 최소 macOS(14)가 바뀌면 cask도 함께 고쳐야 한다.

앱의 업데이트 확인은 태그(`v` 뒤의 숫자)와 앱 버전을 비교하고, 릴리스의 `.zip`을 내려받는다.
그래서 태그 이름과 zip 첨부는 이 꼴을 지켜야 한다.

## 문제를 확인하는 방법

창 상태나 그리기와 얽힌 문제는 자동 테스트로 잡히지 않는다. 앱을 직접 실행해 확인한다.

```bash
# 슬래시 팝업이 뜨는지 + 실제 치수 (스크롤·정렬 확인)
./build/MDemo.app/Contents/MacOS/MDemo --new-memo --demo-slash

# 특정 명령을 치고 엔터까지 눌러 본다 (적용·크래시 확인)
./build/MDemo.app/Contents/MacOS/MDemo --new-memo --demo-command=제목

# 실제 메모를 건드리지 않고 시험 데이터 폴더로 실행 (스크린샷 · 화면 확인용)
./build/MDemo.app/Contents/MacOS/MDemo --data-dir=/tmp/mdemo-demo/Data --show-list -memoList.viewMode board
```

`--data-dir`을 주면 그 폴더의 메모와 창 위치만 읽고 쓴다. 예전 데이터 옮기기와 동기화는 하지 않는다.

앱이 종료됐다면 `~/Library/Logs/DiagnosticReports/MDemo-*.ips`에 원인이 남는다.

## 빌드와 실행

이 프로젝트는 **Xcode 없이 Command Line Tools만으로** 빌드된다.

```bash
make build     # 디버그 빌드 + build/MDemo.app 생성
make run       # 빌드 후 실행 (메뉴바에 메모 아이콘이 나타난다)
make test      # 전 패키지 테스트
make check     # 계층 규칙 · 네트워크 코드 검사

make release   # arm64 + x86_64 유니버설 번들
make dist      # 배포 파일 build/dist/MDemo-vX.Y.Z.zip · .dmg
```

앱은 Dock에 뜨지 않는다(LSUIElement). 종료는 메뉴바 아이콘 → 종료.

앱 아이콘은 코드로 그린다. 고친 뒤 `swift Scripts/draw-icon.swift && Scripts/make-icon.sh`로
`AppIcon.png`와 `AppIcon.icns`를 함께 만든다. 메뉴바 아이콘은 `MenuBarController.menuBarIcon()`에서
같은 모양을 템플릿 이미지로 그린다.

메모리 측정용으로 실행과 동시에 메모를 띄우려면:

```bash
open build/MDemo.app --args --new-memo --new-memo   # 인자 수만큼 창 생성
```

## 기능 추가 규칙

1. 새 마크다운 문법 → `MarkdownEngine`에 `InputRule` 타입 추가. 에디터 본체는 건드리지 않는다.
2. 새 창 동작 → `StickyWindow`에 Behavior 파일 추가. `StickyPanel`을 비대하게 만들지 않는다.
3. 상태 변경은 `MemoStore`를 거친다. UI에서 저장소를 직접 호출하지 않는다.
4. 파일 포맷 변경 → `schemaVersion` 증가 + 마이그레이션 + 왕복 테스트를 한 커밋에 담는다.
5. 커밋 메시지에는 스펙 ID를 쓴다. 예: `feat(WIN-05): 창 위치/크기 자동 저장`

## 개발 환경 메모

- Xcode 미설치 환경이라 `.xcodeproj` 대신 SwiftPM + `Scripts/bundle.sh`로 `.app`을 만든다. 프로젝트 파일이 전부 텍스트라 diff와 병합이 쉽다는 이점도 있다.
- CLT의 `Testing.framework`은 런타임 라이브러리가 빠져 있어 `swift test`가 동작하지 않는다. 그래서 `Packages/TestKit`의 최소 러너를 쓴다. Xcode를 설치하면 각 패키지를 `.testTarget` + swift-testing으로 되돌릴 수 있다.
- Xcode를 설치했다면 라이선스에 한 번 동의해야 툴체인이 열린다. 동의 전에는 `Scripts/toolchain.sh`가 자동으로 Command Line Tools로 되돌려 빌드를 계속한다.

  ```bash
  sudo xcodebuild -license accept && sudo xcodebuild -runFirstLaunch
  ```
- 서명은 ad-hoc(`codesign -s -`). 유료 개발자 계정을 확보하면 `Scripts/bundle.sh`의 서명 줄만 Developer ID로 바꾸면 된다.

### 메모별 암호 잠금 (v0.12.0, 작업 K)

- 메뉴바와 목록 도구 막대의 `새 암호 메모` 또는 `⌘⌥N`으로 만든다. 암호는 대소문자를 구분하는 영문·숫자 4~6자다. 설정 뒤 경고 A의 `이해했습니다`를 선택해야 만들 수 있다.
- 기존 메모는 `암호 메모로 옮기기…`로 새 ID에 옮긴다. 제목·색·그룹·투명도와 첨부를 가져오며 연결과 보드 자리는 가져오지 않는다. 키체인에서 열쇠를 다시 읽어 복호화를 확인한 뒤 원본을 파기한다. 저장·검증 실패 시 새 사본을 정리하고 원본을 보존한다. 비동기 처리 중 원본 내용이 달라져도 옮기기를 중단한다.
- 본문과 첨부는 AES-GCM 256비트로 암호화한다. 메모별 무작위 데이터 열쇠를 PBKDF2-HMAC-SHA256으로 만든 열쇠로 감싼다. 반복 횟수는 기기에서 약 0.5초를 목표로 보정하며 최소 200만 회다. 16바이트 salt·반복 횟수·버전·실패 횟수는 프론트매터에 기록한다. 암호와 원본 데이터 열쇠는 파일에 기록하지 않는다.
- 감싼 데이터 열쇠는 키체인의 `com.wwhalefe.MDemo.lock` 서비스에만 보관한다. 데이터 보호 키체인을 먼저 쓰고, 팀 ID 없이 서명한 지금 배포판처럼 그 키체인을 쓸 수 없으면(-34018) 이 맥의 로그인 키체인에 둔다. 어느 쪽이든 iCloud 키체인 동기화는 끈다. 데이터 보호 키체인에 저장되면 로그인 키체인의 같은 항목은 지운다. 키체인 항목이 없으면 실패 횟수를 올리지 않고 열쇠 없음 안내를 표시한다. 암호 변경은 키체인 항목만 갱신한다.
- 목록에는 제목과 `🔒 잠긴 메모`만 보인다. 본문 검색·복제·이미지 내보내기에서 제외한다. 창에서 암호를 맞힌 동안에는 본문 편집과 기존 노션 호환 형식의 복사(⌘C)가 가능하다. 암호 메모의 첨부는 메모리에서만 복호화하고, Finder 열기·첨부 파일 저장·OCR·AirDrop 받기처럼 파일 주소를 요구하는 경로는 제공하지 않는다.
- 창을 닫거나 내리거나 최소화하면 다시 잠긴다. 맥 잠자기·화면 잠금·앱 종료 때도 편집을 암호화해 저장한 뒤 열쇠와 편집기·되돌리기·이미지 캐시를 비운다.
- 암호를 틀릴 때마다 검증 결과가 나오기 전에 키체인(`<ID>.failures`)과 프론트매터 양쪽에 횟수를 저장하고, 실제 횟수는 둘 중 큰 값이다. 맞히면 둘 다 0으로 돌린다. 감싼 열쇠는 열렸는데 본문만 손상된 경우는 암호가 맞은 것이므로 횟수를 올리지 않고 손상 안내만 한다. 형식에 맞지 않는 입력도 횟수에 넣지 않는다. 9번째 실패 뒤 마지막 기회를 경고하며, 10번째 실패 때 키체인 열쇠부터 삭제하고 메모·첨부를 같은 길이의 난수로 덮어 `fsync`한 뒤 영구 삭제한다. 휴지통과 되돌리기를 통한 복원 경로는 없다. `destroyed.json`의 파기 ID는 동기화 시 합치며, 백업 ZIP 가져오기에서도 거부한다.
- 암호 메모는 이 맥 전용이다. 구글 드라이브 동기화와 MDemo 백업 ZIP에서 제외하고 폴더에 Time Machine 제외 속성을 설정한다. `local-only.json`은 ID 목록만 공유한다. 원본 파기·로컬 전용 기록에 해당하는 다른 기기·구글 드라이브의 활성 및 휴지통 사본도 덮어쓰기와 `fsync` 후 삭제한다. 다른 맥에서의 적용은 해당 맥이 다음 동기화를 실행한 때다.
- `일반 메모로 옮기기…`는 새 일반 ID로 내용과 첨부를 옮긴 뒤 암호 메모를 열쇠까지 파기한다. 새 일반 메모는 다시 동기화·백업 대상이 된다. 파기된 옛 ID의 로컬 전용 기록은 재유입 방지를 위해 유지한다. 백업 전체 교체에서도 이 맥에 있는 암호 메모는 보존한다.

보안 한계: 실제 내용 보호는 AES-GCM과 이 맥 키체인의 데이터 열쇠가 담당한다. 4~6자 암호는 짧으므로 감싼 열쇠까지 탈취한 공격자에게는 대입 공격 여지가 있다. 실패 횟수는 키체인에도 있어 파일만 고쳐서는 되돌릴 수 없지만, 파일과 키체인을 함께 미리 복제하거나 되돌릴 수 있는 공격자에게는 10회 제한을 보장하지 않는다. 키체인 열쇠가 없으면 암호와 암호문만으로는 열 수 없다. 맥을 새로 설치하거나 키체인을 잃으면 잠긴 메모를 복구할 수 없다.

APFS 스냅샷·SSD 블록·구글 드라이브의 과거 버전에 대한 물리적 덮어쓰기는 보장할 수 없다. `fsync`는 로컬 파일의 반영을 요청하며, 드라이브에서는 덮어쓰지 않고 파일을 영구 삭제한다. 잠그기 전 원본의 평문은 Time Machine, 예전 백업 ZIP, 예전 판의 iCloud Drive 폴더, 내보낸 이미지에 남아 있을 수 있으므로 해당 백업은 직접 정리해야 한다. 예전 암호문 사본은 키체인 열쇠를 파기하면 원래 암호로도 열 수 없다. Swift 문자열·CryptoKit 내부 버퍼·AppKit 텍스트·이미지·클립보드·운영체제 스왑의 모든 복제본을 확실히 0으로 덮는 것은 보장할 수 없으며, 관리하는 `Data`와 편집기 버퍼만 가능한 범위에서 덮고 참조를 해제한다.

배포 확인: 현재 번들 스크립트는 ad-hoc 서명을 사용하므로 열쇠는 로그인 키체인에 들어간다(이 맥에서 만들기 · 열기 · 10회 파기까지 확인). 앱을 업데이트하면 서명이 바뀌어 macOS가 "MDemo가 키체인을 사용하려고 합니다"라고 물을 수 있다. 로그인 암호를 넣고 `항상 허용`을 고르면 된다. 키체인 접근이 거부되면 암호 메모 만들기를 중단하며 평문 대체 저장은 하지 않는다. 암호 칸 옆의 `암호…` 단추는 macOS 암호 자동 입력 제안이다.
