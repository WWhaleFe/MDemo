# 마일스톤별 측정 기록

메모리 최소화가 제1 요구사항이므로(설계서 §4-5) 마일스톤마다 아래 값을 기록한다.
게이트를 넘으면 기능 추가를 멈추고 원인부터 잡는다.

| 항목 | 목표 | 근거 |
|---|---|---|
| 번들 크기 | 30MB 이하 | NFR-01 |
| 상주 메모리 (창 0개) | 50MB 이하 | NFR-09 |
| 메모 10개 표시 | 120MB 이하 (스펙 150MB보다 엄격한 내부 목표) | NFR-02 |
| 창 닫은 후 회수 | 본문·이미지 메모리 해제 | NFR-10 |

측정 방법: `make mem` (RSS 기준) 또는 메뉴바 → 메모리 항목(phys_footprint 기준).
RSS는 공유 라이브러리를 포함하므로 실제 앱 점유량보다 크게 잡힌다.

---

## M0 — 골격 (2026-08-26)

| 항목 | 측정값 | 판정 |
|---|---|---|
| 번들 크기 | 404KB | 통과 (목표 30MB) |
| 상주 메모리 (창 0개) | 47.7MB RSS | 통과 (목표 50MB) |
| 메모 10개 표시 | 65.7MB RSS | 통과 (목표 120MB) |
| 창 1개당 증가분 | 약 1.8MB | — |
| 창 닫은 후 회수 | 미측정 | M1로 이월 |

확인된 동작:

- 창 레이어 3(floating) — 항상 위 표시가 실제로 적용됨 (WIN-03)
- `alphaValue = 1.0` 유지 — 투명도는 배경 레이어와 텍스트에만 적용 (설계서 §3 원칙)
- 창 크기 300×320으로 생성, 겹치지 않게 어긋나 배치

메모: 창 0개 상태의 47.7MB는 AppKit·Swift 런타임 등 공유 라이브러리가 대부분이다.
창 하나당 실제 증가분(약 1.8MB)이 앞으로 관리할 값이며, M1에서 본문·서식이 들어가면
이 수치가 어떻게 변하는지가 관건이다.
