# 메모 목록 개편 기획 - 아이콘 톤 · 4가지 보기 · 파이프라인

> 상태: **확정 대기** (2026-11-24 작성). 아래 "확정할 것"에 답을 받은 뒤 구현한다.

## 1. 시장 조사 요약

### 1-1. 비교 대상

| 분류 | 제품 | 목록 보기 | 메모 간 연결 | 플로팅(바탕화면) 메모 |
|---|---|---|---|---|
| 시각 지식관리 | Heptabase | 화이트보드 · 표 · 칸반 | 카드 사이 선을 손으로 긋는다. 2026-11 기준 마인드맵 · 그리드 스냅 · 스마트 가이드 추가 | 없음 |

### 1-2. 보이는 빈자리

1. **스티커 메모 앱은 "띄우기"는 잘하지만 "엮기"가 없다.** 목록 · 그리드까지가 한계다. 연결이 있는 Sticky Runes는 바탕화면 위 화살표 장식에 그친다.
2. **지식관리 앱은 "엮기"는 잘하지만 "띄우기"가 없다.** Heptabase · Obsidian · Scrintal 모두 창 안의 캔버스다.
3. 둘 다 연결이 **손으로 긋는 선**일 뿐, 연결에 의미(순서 · 흐름)가 없다.

### 1-3. MDemo가 설 자리

> **"화면에 떠 있는 메모를, 보드에서 파이프로 엮는다."**

- 보드에서 이은 파이프가 메모 데이터(프론트매터)에 남으므로, 플로팅 메모 창에서도 "다음 메모 → / ← 이전 메모"로 따라갈 수 있다. 이건 위 표의 누구도 하지 않는다.
- 파이프는 방향이 있는 흐름이다. "아이디어 → 할 일 → 결과"처럼 순서를 담는다. 마인드맵(가지)과 파이프라인(줄기)을 한 기능으로 쓴다.
- 파이프 한 줄을 통째로 띄우기 · 숨기기 · 나란히 놓기가 된다 (기존 "창 나열"의 확장).

## 2. 디자인 톤 - 아이콘에서 뽑은 규칙

아이콘(`App/Resources/AppIcon.png`)의 요소를 그대로 UI 문법으로 옮긴다.

| 아이콘 요소 | UI 규칙 |
|---|---|
| 밝은 회색 바탕 (#ECEDEF~#E4E5E8) | 목록 창 바탕. 순백 대신 아주 옅은 회색 |
| 오프화이트 둥근 카드 (#FAFAFA, 모서리 약 22%) + 아래로 퍼지는 부드러운 그림자 | 모든 메모 카드 · 행. 테두리 대신 그림자 한 단계로 층을 나눈다 |
| 먹색 굵은 둥근 막대 (#1C1D20) | 글자 · 아이콘 · 파이프 선. 선 끝은 항상 둥글게(round cap) |
| 라임 점 (#D4F53C) | **유일한 강조색.** 연결 단자(포트), 선택 표시, 띄워진 메모 표시에만 쓴다. 넓은 면에는 쓰지 않는다 |
| 회색 점선 + 빗금 뒷카드 | "아직 없는 것": 빈 칸, 끌어다 놓을 자리, 숨긴 메모, 연결 대기 상태 |

- 메모 고유 배경색(파스텔 8색)은 카드 전체를 칠하지 않고 **제목 앞 작은 네모 칩**으로만 보인다. (둥근 점은 라임 전용이라 모양으로도 구분) 그래야 아이콘의 흰 카드 톤이 유지된다. (보드 보기만 예외로 옅게 칠하는 옵션 검토)
- 글꼴: 시스템 SF Pro + 한글은 Apple SD Gothic Neo. 본문 13~14pt 400~500, 제목 600~700, 작은 글씨 최소 12pt.
- 다크 모드: 바탕 #18191B, 카드 #232427, 글자 #EDEDED, 라임은 그대로.
- 금지: 보라 그라디언트, 글로우, 이모지 라벨, 깜빡이는 요소 (unslop 기준).

## 3. 네 가지 보기

툴바 가운데에 보기 전환 세그먼트 `목록 | 그리드 | 벤토 | 보드` (⌘1~⌘4). 사이드바(그룹 · 휴지통)와 검색은 네 보기가 같이 쓴다.

### 3-1. 목록 (지금 화면 다듬기)
- 표 머리글 없이 날짜 묶음(오늘 · 이번 주 · 지난달)별 흰 상자 안에 줄을 쌓는다. 버튼을 늘어놓은 상단 줄, 눈 아이콘, 오른쪽 미리보기 칸은 두지 않는다.
- 한 줄: 색 칩 · 제목 · 본문 한 줄 · 흐름 칩 · 라임 점(떠 있음) · 시각. 선택한 줄 아래에 그 메모가 속한 흐름이 펼쳐진다.
- 새 열: **연결 수** (`⟜ 3`). 누르면 보드에서 그 메모 위치로 이동.

### 3-2. 그리드 (일반 그리드)
- 같은 크기 카드(약 200×160). 제목 + 본문 앞 4줄 미리보기 + 색 칩 + 수정일.
- 창 폭에 맞춰 열 수가 바뀐다. 정렬은 목록과 공유.

### 3-3. 벤토 그리드
- 카드 크기를 4단계(1×1, 2×1, 1×2, 2×2)로 두고, **자동 배정 + 손으로 바꾸기**:
  - 자동: 고정(핀) 메모 · 최근 수정 · 연결이 많은 메모(허브)는 크게, 짧은 메모는 작게.
  - 수동: 카드 모서리를 끌거나 우클릭 "크기"로 고정.
- 연결된 메모는 서로 가까이 모이도록 배치하고, 카드 사이 이음 부분에 작은 라임 점으로 "이어져 있음"만 표시한다 (선은 그리지 않음).
- 큰 카드는 체크리스트 · 표도 그대로 렌더링한 미리보기.

### 3-4. 보드 (화이트보드 + 파이프라인) - 대표 기능
- 무한 캔버스. 확대 · 축소(핀치, ⌘+/-), 이동(스페이스+드래그, 두 손가락).
- 메모 카드를 자유 배치. 목록 · 그리드에서 끌어다 놓거나, 보드 빈 곳을 두 번 눌러 새 메모.
- **파이프 잇기**: 카드에 마우스를 올리면 네 변에 라임 포트가 나온다. 끌어서 다른 카드에 놓으면 연결. 끄는 동안은 점선, 놓으면 먹색 둥근 선으로 굳는다.
- 파이프 종류 2가지:
  - **흐름**(화살표, 방향 있음): 순서 · 단계. 기본값.
  - **관련**(점선, 방향 없음): 느슨한 연관.
- 파이프에 짧은 이름표 달기(선택), 색은 먹색 하나 + 선택 시 라임.
- **줄기 동작**: 파이프 위에서 우클릭 → "이 흐름 모두 띄우기 / 순서대로 나란히 놓기 / 숨기기".
- 정렬 도우미: 그리드 스냅, 자동 정리(흐름 = 왼→오, 관련 = 방사형 마인드맵).
- 붙여넣기: 텍스트 · 마크다운을 보드에 붙이면 새 메모 카드. 여러 줄 목록을 붙이면 "줄마다 메모 + 순서대로 파이프"로 만들지 묻는다.
- 미니맵(우하단)과 "전체 보기"(⌘0).

### 3-5. 플로팅 메모 창과의 연결 (차별점)
- 메모 창의 서식바(`FormatToolbarView`, 위·아래·좌·우·숨김 위치 설정)는 지금 그대로 유지한다. 이번 개편은 목록 창만 바꾼다.
- 연결된 메모 창 하단에 얇은 줄: `← 이전 메모 제목 · 다음 메모 제목 →`. 누르면 그 메모를 띄운다.
- 메모 본문에서 `[[제목]]`을 입력하면 관련 파이프가 자동 생성 (2단계에서 검토).

## 4. 데이터 설계 (기존 구조에 맞춤)

현재 메모 = 마크다운 파일 + YAML 프론트매터(`MemoMeta`, 기기 간 공유), 창 위치 등은 `DeviceMemoState`(기기별).

- **파이프** → 출발 메모 프론트매터에 저장 (기기 간 공유, 파일만 봐도 관계가 보임):
  ```yaml
  links:
    - to: 01HX...ID
      kind: flow      # flow | related
      label: 다음 단계  # 선택
  ```
  `schemaVersion` 2 → 3. 없으면 빈 배열로 읽으므로 되돌릴 수 있음. 상대 메모가 삭제되면 링크는 휴지통 복원을 위해 남기고 화면에만 숨김.
- **보드 위치 · 벤토 크기** → 별도 파일 `board.json`(동기화 폴더, 기기 간 공유): `{ memoID: {x, y, w, h, bentoSize} }`. 메모 파일을 건드리지 않으므로 배치만 바꿔도 동기화 충돌이 안 생김.
- **마지막 보기 · 확대율 · 보드 시점** → 기기별 설정(UserDefaults).

## 5. 구현 단계 (제안)

| 단계 | 내용 | 규모 |
|---|---|---|
| 0 | 디자인 토큰(색 · 반경 · 그림자) 정리, 보기 전환 툴바 | 작음 |
| 1 | 목록 다듬기 + 그리드 보기 | 작음 |
| 2 | 데이터: `links` 프론트매터(v3) + `board.json` + 테스트 | 중간 |
| 3 | 보드: 캔버스 · 카드 배치 · 확대/이동 · 파이프 잇기/지우기 | 큼 |
| 4 | 보드: 줄기 동작(모두 띄우기 등), 자동 정리, 붙여넣기 | 중간 |
| 5 | 벤토 그리드 (자동 크기 + 연결 기반 배치) | 중간 |
| 6 | 플로팅 창 이전/다음 줄, `[[제목]]` 링크 | 중간 |

기술: 보드는 SwiftUI `Canvas`(선) + 카드 뷰 겹치기로 시작하고, 메모 수백 개에서 느리면 AppKit 레이어로 바꾼다. 벤토는 SwiftUI `Layout` 프로토콜로 직접 배치.

## 6. 확정할 것

1. 이름: 연결 기능을 **"파이프"**로 부를지 (대안: 잇기, 흐름, 줄)
2. 파이프 종류를 흐름 + 관련 2가지로 할지, 처음엔 흐름 하나만 할지
3. 보드를 하나만 둘지, 그룹마다 / 여러 개 만들 수 있게 할지
4. 보드 카드에 메모 고유 파스텔색을 칠할지 (아이콘 톤 유지를 위해 기본은 띠만)
5. 벤토 크기: 자동 + 수동(제안) / 수동만
6. 구현 순서: 위 0→6 순서(목록 · 그리드 먼저) / 보드 먼저
