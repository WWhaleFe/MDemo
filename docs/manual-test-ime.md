# 한글 입력 수동 테스트 체크리스트 (NFR-08)

한글 조합 중 자동 변환이나 서식 적용이 끼어들면 글자가 깨진다.
자동화가 불가능한 영역이므로 M1 이후 에디터를 건드리는 모든 변경에서 이 목록을 확인한다.

원칙: 조합 중(`hasMarkedText() == true`)에는 어떤 속성 변경도 하지 않고,
조합이 확정된 뒤 보류했던 변환을 적용한다.

## 실행 방법

```bash
make run
open build/MemoApp.app --args --new-memo
```

입력기를 한글로 바꾼 뒤 아래를 순서대로 확인한다.

## 체크 항목

| # | 상황 | 입력 | 기대 결과 | 결과 |
|---|---|---|---|---|
| 1 | 제목 변환 중 조합 | `# ` 입력 후 곧바로 `안녕하세요` | 제목 서식이 적용되고 글자가 온전함 | |
| 2 | 조합 중 굵게 | `**한글` 까지 입력하고 조합 상태에서 대기 | 조합이 풀리거나 글자가 깨지지 않음 | |
| 3 | 굵게 완성 | `**한글**` 완성 | 굵게 적용, 텍스트는 "한글" | |
| 4 | 조합 중 Cmd+B | `한글` 조합 중 Cmd+B | 조합이 확정된 뒤 서식 적용, 글자 유실 없음 | |
| 5 | 체크박스 | `- [ ] 장보기` | 체크박스 생성, 뒤 한글 온전함 | |
| 6 | 목록 자동 이어가기 | `- 사과` 엔터 `배` | 두 번째 줄도 글머리 기호, 조합 정상 | |
| 7 | 슬래시 명령 | `/제목` 입력 | 한글 명령 필터링 동작, 조합 중 팝업이 입력을 가로채지 않음 | |
| 8 | 조합 중 Undo | 변환 직후 Cmd+Z | 원문 마크다운 기호가 복원됨 (MD-13) | |
| 9 | 조합 중 창 전환 | 조합 상태에서 다른 창 클릭 | 조합이 안전하게 확정되고 저장됨 | |
| 10 | 빠른 연속 입력 | 긴 한글 문장을 빠르게 입력 | 누락·중복 글자 없음 | |

## 슬래시 팝업 (SL-01~03)

창 상태에 좌우되는 동작이라 단위 테스트로 잡히지 않는다. 실행한 앱에서 확인한다.

실행 인자로 재현할 수 있다. 앱을 직접 실행하면 팝업의 실제 치수를 표준 오류로 찍어 준다 —
계산한 크기와 화면이 어긋나는지 눈으로 확인할 수 있다:

```bash
./build/MemoApp.app/Contents/MacOS/MemoApp --new-memo --demo-slash
```

출력 예시 (정상 상태):

```
팝업 창 320.0 × 386.0
표를 담는 영역 312.0 × 378.0
표 내용 높이 378.0  (행 9개, 행 높이 42.0)
첫 행 위치 y=0.0, x=0.0, 너비 312.0
스크롤 발생: 아니오
```

`표 내용 높이 > 표를 담는 영역 높이`이거나 `첫 행 위치 y`가 0이 아니면 스크롤이 생긴다.

| # | 상황 | 기대 결과 | 결과 |
|---|---|---|---|
| 1 | 빈 줄에서 `/` | 명령 9개가 모두 보인다 | |
| 2 | 이어서 `체크` | 체크박스가 맨 위로 좁혀진다 | |
| 3 | ↑↓ | 선택이 움직인다 | |
| 4 | 엔터 | 해당 서식이 적용되고 팝업이 닫힌다 | |
| 5 | 적용 직후 타자 | 글자가 정상 입력된다 (먹통 아님) | |
| 6 | 적용 직후 방향키 | 커서가 움직인다 | |
| 7 | 슬래시 명령 5회 반복 | 매번 정상 동작, 입력이 죽지 않는다 | |
| 8 | Esc | 팝업만 닫히고 입력은 유지된다 | |
| 9 | 팝업 뜬 상태로 창 드래그 | 팝업이 정리된다 | |
| 10 | 문장 중간의 `앱/설정` | 팝업이 뜨지 않는다 | |

## 실패 시 확인 순서

1. `LiveFormatController`가 `isComposingText`를 검사하는가
2. 변환이 `processEditing` 안에서 즉시 실행되고 있지 않은가 (조합 확정 후로 미뤄야 한다)
3. `NSTextStorage` 속성 변경 범위가 조합 영역과 겹치지 않는가
